# Sange configuration schema

The single `SangeConfig` Pydantic v2 model is the only configuration surface every Sange subsystem reads from. `SangeConfig()` with no arguments yields a valid object representing the **default-minimal** configuration; `.sange/config.toml` is entirely optional.

## Precedence chain

Per §6.3, configuration layers merge with **rightmost wins** on conflict:

```text
built-in defaults
  ← /etc/sange/config.{toml,json}
    ← ~/.sange/config.{toml,json}
      ← ${repo}/.sange/config.{toml,json}
        ← SANGE__SECTION__FIELD environment variables
          ← CLI flags
```

JSON wins over TOML at the same level when both exist (machine-authoritative per ADR-009). The loader emits a warning on conflict.

## Environment-variable overrides

Environment variables matching `SANGE__SECTION__FIELD=value` map onto the nested model. `__` (two underscores) is the nesting separator. Examples:

```bash
SANGE__VARIANTS__DEFAULT_STAGE=staging
SANGE__AUDIT__VERBOSITY=elevated
SANGE__AUDIT__ROTATION_DAYS=30
SANGE__TELEMETRY__ENABLED=false
SANGE__VARIANTS__STAGES=dev,staging,production   # comma-list
```
