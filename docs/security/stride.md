## Full threat details

Each threat below names its attack vector, blast radius, full mitigation list, affected subsystems, and prompt-anchor references.

### `T-001` — Curl-pipe-sh installer compromise

- **Category:** Spoofing
- **Blast radius:** Critical
- **Attack vector:** Attacker hosts a malicious binary at the installer URL or MITMs the connection to substitute their own script.
- **Affected:** §7.1 Installer, §14.3 v1.0 release engineering
- **References:** §11, §7.1

**Mitigations:**

  - Pinned checksums for every installer artifact
  - Sigstore signatures verified before execution
  - Mirror plan with hash-pinned secondary distribution channel
  - Reproducible builds with SLSA 3 provenance
  - TLS 1.3 + HSTS on the install host

### `T-002` — Hostile MCP server impersonation

- **Category:** Spoofing
- **Blast radius:** High
- **Attack vector:** Malicious MCP server poses as a trusted one and feeds the prompt-enhancer instructions designed to exfiltrate repo content or run arbitrary tools.
- **Affected:** §6.7 MCP, §8.2.12 AI Configuration
- **References:** §11, §6.7

**Mitigations:**

  - Allowlist of permitted MCP servers per project
  - Capability prompts before each tool call
  - Response-shape validation before execution
  - Revocable per-project; audit-logged

### `T-003` — Cloudflare Tunnel token theft

- **Category:** Spoofing
- **Blast radius:** High
- **Attack vector:** Leaked tunnel token allows an attacker to bind a hostile cloudflared process to the user's tunnel, intercepting Web UI traffic.
- **Affected:** §8.5.1 Cloudflare Tunnel, §8.2.11 Secrets
- **References:** §11, §8.5.5

**Mitigations:**

  - Tunnel tokens stored in OS keychain only
  - Rotation supported (and surfaced as a doctor recommendation)
  - Tunnel bound to a single Sange instance (sange identity check)
  - Anomalous session detection (impossible travel, new device)

### `T-004` — Web UI passkey/PIN spoofing

- **Category:** Spoofing
- **Blast radius:** High
- **Attack vector:** Attacker brute-forces the PIN fallback or replays a captured WebAuthn assertion.
- **Affected:** §8.3 Web UI Security, §8.1 Auth stack
- **References:** §11, §8.3

**Mitigations:**

  - WebAuthn passkey primary (replay-resistant by design)
  - PIN fallback rate-limited with abuse-lockout
  - Optional TOTP second factor on PIN
  - Password alternative uses Argon2id + HIBP k-anonymity check

### `T-010` — Prompt injection via repo content

- **Category:** Tampering
- **Blast radius:** Critical
- **Attack vector:** Malicious commit messages, file contents, dependency READMEs, hostile diffs, or compromised MCP-server responses contain instructions that hijack the LLM's behavior.
- **Affected:** §6.7 AI subsystem, §6.7.1 Prompt enhancer
- **References:** §11, §5.3, §6.7

**Mitigations:**

  - Delimiter discipline: untrusted input wrapped in <untrusted_input> blocks
  - Output validation: response shape enforced before execution
  - Confirmation gates for any repo-modifying action
  - Content firewall scans LLM input AND output for known patterns
  - Defense-in-depth: ≥3 independent controls per the prompt's §5.3 mandate

### `T-016` — Bundle signature substitution

- **Category:** Tampering
- **Blast radius:** Critical
- **Attack vector:** Compromised CI substitutes a malicious binary while keeping the signature file.
- **Affected:** §6.9 Release bundling
- **References:** §11, §6.9

**Mitigations:**

  - Sigstore + cosign signing of every bundle artifact
  - SLSA 3 provenance attestation
  - `sange bundle verify-remote <url>` checks signature against canonical key
  - Bundle channels are monotonic; `stable` cannot regress to `beta`

### `T-017` — Supply chain dependency compromise

- **Category:** Tampering
- **Blast radius:** Critical
- **Attack vector:** Malicious update to a dependency (pip, composer, npm) lands and Sange pulls it on the next install.
- **Affected:** §14 release engineering, §8.4 Web UI ADRs
- **References:** §11, §5.2

**Mitigations:**

  - SLSA 3 builds with reproducible provenance
  - SBOM per release (CycloneDX)
  - Dependency pinning in pyproject.toml + composer.json + package.json
  - `pip-audit`, `composer audit`, `npm audit` in CI
  - OpenSSF Scorecard ≥ 8.0 target

### `T-012` — Symlink / path traversal in `.sange/` ops

- **Category:** Tampering
- **Blast radius:** High
- **Attack vector:** Attacker plants a symlink inside the repo (`.sange/audit` → `/etc/passwd`) and lets Sange's write helpers follow the link.
- **Affected:** §6.4 `.sange/` folder, §7.0.6 subprocess streaming
- **References:** §11

**Mitigations:**

  - Path canonicalization before every write
  - Refusal of paths that escape the repo root
  - Atomic write helpers use `os.replace` semantics, not `open(symlink, 'w')`

### `T-014` — Audit-log tampering

- **Category:** Tampering
- **Blast radius:** High
- **Attack vector:** Attacker edits the `.sange/audit/*.jsonl` hash chain or redirects future writes to `/dev/null` to hide their tracks.
- **Affected:** §7.0.7 Hash-chained audit
- **References:** §11, §7.0.7, §6.11.6

**Mitigations:**

  - Append-only files with sha256 hash chain (`prev_hash` link)
  - `sange audit verify` replays the chain and detects any mismatch
  - Refusal to write when audit destination is `/dev/null`
  - Dual-write to per-repo + global audit stores
  - Optional forward to external SIEM

### `T-015` — Race conditions on gitignore-swap

- **Category:** Tampering
- **Blast radius:** High
- **Attack vector:** Two `sange publish` invocations or a concurrent `git` command corrupt the dev↔prod gitignore swap.
- **Affected:** §6.5 Gitignore-swap, §6.5.2 Variant matrix, §7.10 `sange recover`
- **References:** §11, §6.5

**Mitigations:**

  - File lock + atomic rename for the swap operation
  - Abort on detected concurrent VCS op
  - SIGKILL recovery file on disk (replayed by `sange recover`)
  - Per-§6.5.2 variant matrix: stage-locked operations refuse mismatched variants

### `T-018` — Malicious plugin injection

- **Category:** Tampering
- **Blast radius:** High
- **Attack vector:** Third-party plugin runs arbitrary code with Sange's privileges, or a build-time injection bypasses signature checks.
- **Affected:** §7.9 Plugin system
- **References:** §11

**Mitigations:**

  - Signed plugin manifests (per ADR-020)
  - Capability declarations reviewed at install
  - Network/FS access denied-by-default
  - Sandboxed execution surface for third-party code
  - Signature check at install AND runtime

### `T-011` — Config tampering (host-side)

- **Category:** Tampering
- **Blast radius:** Medium
- **Attack vector:** Another process on the user's machine writes to `~/.sange/` or the per-repo `.sange/config.toml`, redirecting AI providers, secret resolvers, or audit destinations.
- **Affected:** §6.3 Config, §7.1 Doctor
- **References:** §11

**Mitigations:**

  - `~/.sange/` mode `0700`
  - Optional signed-config feature for paranoid setups
  - Doctor warns on permission drift

### `T-013` — Commit-JSON tampering

- **Category:** Tampering
- **Blast radius:** Medium
- **Attack vector:** Attacker (or accidental editor save) modifies a `.sange/commits/NNNN-*.json` to bypass the §6.8 lifecycle's review gate.
- **Affected:** §6.8 Commit lifecycle
- **References:** §11, §6.8

**Mitigations:**

  - Sidecar integrity hash in `.sange/commits/.audit/`
  - CAS update on the `status` field
  - Warning + audit-log entry on hash mismatch
  - Status transitions are forward-only except via explicit `sange commits reopen`

### `T-020` — Operator denies a destructive purge ran

- **Category:** Repudiation
- **Blast radius:** Medium
- **Attack vector:** After a `sange purge execute` rewrites history and force-pushes, the operator denies it was them (claiming a compromised account or shared terminal).
- **Affected:** §6.11 Purge subsystem, §7.0.5 Typed-phrase gates
- **References:** §11, §6.11.6

**Mitigations:**

  - Hash-chained audit JSONL records actor, timestamp, typed-phrase verbatim
  - Per-session nonce in the typed phrase (§7.0.5) — non-replayable
  - Dual-store audit: per-repo + global mirror under `~/.sange/audit/`
  - Optional SIEM forward for tamper-evident off-host record

### `T-021` — AI-generated commit lacks provenance

- **Category:** Repudiation
- **Blast radius:** Low
- **Attack vector:** Hard to determine after the fact whether a commit message came from a human or from the AI subsystem.
- **Affected:** §6.7 AI subsystem, §6.8 Commit lifecycle
- **References:** §11, §6.8.3

**Mitigations:**

  - Every AI-generated commit JSON records provider, model, prompt_version, template_id, cost_estimate, token counts
  - Audit chain entry on every commit lifecycle transition
  - `sange ai preview` shows the exact prompt that would be sent

### `T-030` — Secret exfiltration via AI provider

- **Category:** Information Disclosure
- **Blast radius:** Critical
- **Attack vector:** Diffs containing secrets, API keys, or PII are sent to an external AI provider as part of a commit-message generation request.
- **Affected:** §6.7 AI subsystem, §6.7.1 Prompt enhancer, §12 Telemetry
- **References:** §11, §6.7

**Mitigations:**

  - Redaction layer scrubs diffs before egress (high-entropy strings, known secret patterns, configurable PII patterns)
  - Variant-aware AI provider selection: production stages can pin internal-only providers (Bedrock, Ollama)
  - `sange ai preview` shows the exact payload before sending
  - Per-variant provider selection (§6.5.2.8)

### `T-031` — Container VCS secret leak

- **Category:** Information Disclosure
- **Blast radius:** High
- **Attack vector:** Secrets baked into image layers, leaked via env vars, exposed in process memory via core dumps, or hijacked from the SSH agent socket.
- **Affected:** §6.10 Container VCS Secret Mgmt
- **References:** §11, §6.10

**Mitigations:**

  - BuildKit secrets mounted as tmpfs (never in image layers)
  - Env vars zeroed-out after startup
  - `mlock` to prevent swap of secret-bearing memory
  - `RLIMIT_CORE=0` to disable core dumps
  - `sange doctor --container` audits the running container

### `T-032` — DNS rebinding against `sange.test`

- **Category:** Information Disclosure
- **Blast radius:** High
- **Attack vector:** Attacker controls a domain that resolves first to a public IP, then (after the user's browser caches CORS) to `127.0.0.1`, allowing malicious JS to make requests to the local Sange web UI.
- **Affected:** §8.3 Web UI security
- **References:** §11, §8.3

**Mitigations:**

  - Host-header validation against allowlist (only `sange.test`, `localhost`, user-configured LAN/remote names)
  - Same-origin only (CORS disabled by default)
  - Strict Origin/Referer validation

### `T-033` — Token theft from web UI credential store

- **Category:** Information Disclosure
- **Blast radius:** High
- **Attack vector:** Compromise of `~/.sange/web.db` or the OS keychain entries exposes VCS access tokens (GitHub PAT, GitLab token, etc.).
- **Affected:** §6.10 Secrets, §8.2.11 Secrets module
- **References:** §11, §6.10

**Mitigations:**

  - OS keychain default; database stores metadata + scoped references only
  - Scoped tokens with minimum-privilege scopes
  - Rotation reminders surfaced in `sange doctor`
  - Never logged; redacted in audit chain

### `T-034` — IPC tampering

- **Category:** Information Disclosure
- **Blast radius:** High
- **Attack vector:** Local malware intercepts unauthenticated JSON-RPC between CLI/UI and the `sanged` daemon, leaking commit content or secret references.
- **Affected:** §6.1 IPC, §8.5.5 Remote-mode obligations
- **References:** §11, §8.5

**Mitigations:**

  - HMAC-signed JSON-RPC for local IPC; rotating shared secret in memory only
  - mTLS for remote daemon access (mandatory in remote mode)
  - Bind address `127.0.0.1` by default
  - `sange web remote audit` refuses to start if mTLS missing in remote mode

### `T-040` — Daemon resource exhaustion (local)

- **Category:** Denial of Service
- **Blast radius:** Low
- **Attack vector:** A loop in user code or a malicious local actor floods the `sanged` JSON-RPC endpoint with requests.
- **Affected:** §6.1 IPC, §7.0.6 subprocess discipline
- **References:** §11

**Mitigations:**

  - Per-route, per-IP rate limiting on the daemon
  - Daemon runs as user (not root); no setuid
  - Capability dropping post-start

### `T-041` — Audit-log filesystem exhaustion

- **Category:** Denial of Service
- **Blast radius:** Low
- **Attack vector:** Attacker spams operations to balloon the audit JSONL until disk fills.
- **Affected:** §7.0.7 audit, §13 Observability
- **References:** §11

**Mitigations:**

  - Audit log rotation by configurable size/age (default weekly)
  - Doctor warns on disk-low
  - Telemetry rolled at 7-day boundary by default

### `T-050` — Daemon privilege escalation

- **Category:** Elevation of Privilege
- **Blast radius:** Critical
- **Attack vector:** Hostile input to the daemon exploits a vulnerability to escape its user-level sandbox.
- **Affected:** §6.1 Daemon, §6.2 Adapter Protocol
- **References:** §11

**Mitigations:**

  - Run as user, no setuid binary anywhere in the install
  - Capability dropping where applicable (CAP_NET_BIND, etc.)
  - Strict input validation on every IPC method
  - Pydantic v2 schema enforcement on every payload

### `T-051` — IPC daemon accidentally exposed on 0.0.0.0

- **Category:** Elevation of Privilege
- **Blast radius:** Critical
- **Attack vector:** Misconfiguration binds `sanged` to all interfaces, letting any network peer drive Sange operations.
- **Affected:** §8.5 Remote topologies
- **References:** §11

**Mitigations:**

  - Bind `127.0.0.1` by default; remote mode requires explicit opt-in + setup wizard
  - `sange web remote audit` checks bind address before allowing remote mode
  - HMAC required for local; mTLS required for remote

### `T-052` — Tailscale tagged-device escalation

- **Category:** Elevation of Privilege
- **Blast radius:** High
- **Attack vector:** Attacker compromises a low-privileged tagged device in the user's tailnet and uses it to reach the Sange remote UI.
- **Affected:** §8.5.2 Tailscale, §8.5.5 Remote obligations
- **References:** §11, §8.5

**Mitigations:**

  - ACLs for fine-grained device/user access on Tailscale
  - MFA mandatory on at least one role in remote mode
  - IP allowlist optional but recommended even within tailnet
  - Anomalous-session detection (impossible travel)

### `T-053` — VPS provider control-plane compromise

- **Category:** Elevation of Privilege
- **Blast radius:** High
- **Attack vector:** Hetzner/DigitalOcean/AWS console takeover exposes the VPS hosting Sange's remote web UI to attacker.
- **Affected:** §8.5.4 VPS reverse-proxy
- **References:** §11

**Mitigations:**

  - mTLS mandatory in remote mode (defense beyond provider)
  - MFA mandatory on the cloud account
  - Backups stored off-provider (per §6.12 kit recommendation)
  - Audit log forwarded to external SIEM where possible

## How to extend the catalog

- Add a new threat → append a `_t(...)` literal to `THREATS` in `tools/generators/threat_model_table.py`. Use the next free `T-NNN` in the block (Spoofing T-001..T-009, Tampering T-010..T-019, etc.).
- Add a new mitigation to an existing threat → edit the threat's `mitigations` tuple; the test suite enforces ≥1 mitigation.
- Add a new STRIDE category — refuse. The six categories are canonical.
- Regenerate → `python tools/generators/all.py --only T-G-012 --write`.
- Verify integrity → `python tools/generators/verify_generated.py`.
